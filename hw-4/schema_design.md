# Проектирование документной модели MongoDB

## Вариант 5: Мессенджер https://slack.com/intl/en-gb/ 

## 1. Краткое описание системы

Проектируемая система - корпоративный мессенджер: пользователи могут находить друг друга по логину, имени и фамилии, создавать групповые чаты, добавлять участников, писать сообшения в групповые чаты и обмениваться личными PtP-сообщениями.

Основные данные системы:

- пользователь;
- групповой чат;
- PtP-чат;
- сообщения групповых чатов;
- сообщения PtP-чатов.

Для MongoDB выбрана модель, в которой основные сущности хранятся в отдельных коллекциях, а небольшие зависимые структуры встраиваются внутрь документов.  Сообщения вынесены в отдельные коллекции, так как их количество постоянно растет и для них нужна постраничная загрузка.

## 2. Список коллекций

В базе данных используются следующие коллекции:

| Коллекция | Назначение |
|---|---|
| `users` | Пользователи системы |
| `group_chats` | Групповые чаты и состав участников |
| `group_messages` | Сообщения групповых чатов |
| `ptp_chats` | Личные чаты между двумя пользователями |
| `ptp_messages` | Сообщения в личных чатах |

## 3. Коллекция `users`

Документ пользователя:

```json
{
  "_id": {
    "$oid": "665000000000000000000001"
  },
  "login": "ivan.petrov",
  "first_name": "Иван",
  "last_name": "Петров",
  "display_name": "Иван Петров",
  "email": "ivan.petrov@example.com",
  "created_at": {
    "$date": "2026-05-25T10:00:00Z"
  },
  "updated_at": {
    "$date": "2026-05-25T10:00:00Z"
  }
}
```

Назначение полей:

| Поле | Тип | Описание |
|---|---|---|
| `_id` | `ObjectId` | Уникальный идентификатор пользователя |
| `login` | `string` | Уникальный логин пользователя |
| `first_name` | `string` | Имя |
| `last_name` | `string` | Фамилия |
| `display_name` | `string` | Отображаемое имя |
| `email` | `string` | Почта пользователя |
| `created_at` | `date` | Дата создания |
| `updated_at` | `date` | Дата последнего изменения |

Пользователь хранится в отдельной коллекции, потому что он используется в разных частях системы: в групповых чатах, PtP-чатах и сообщениях. Дублировать полный документ пользователя внутри каждого чата не нужно: это привело бы к лишним обновлениям при изменении профиля.

## 4. Коллекция `group_chats`

Документ группового чата:

```json
{
  "_id": {
    "$oid": "665000000000000000000101"
  },
  "name": "Команда разработки",
  "description": "Рабочий чат проекта",
  "created_by": {
    "$oid": "665000000000000000000001"
  },
  "members": [
    {
      "user_id": {
        "$oid": "665000000000000000000001"
      },
      "role": "owner",
      "joined_at": {
        "$date": "2026-05-25T10:05:00Z"
      }
    },
    {
      "user_id": {
        "$oid": "665000000000000000000002"
      },
      "role": "member",
      "joined_at": {
        "$date": "2026-05-25T10:10:00Z"
      }
    }
  ],
  "created_at": {
    "$date": "2026-05-25T10:05:00Z"
  },
  "updated_at": {
    "$date": "2026-05-25T10:10:00Z"
  }
}
```

Назначение полей:

| Поле | Тип | Описание |
|---|---|---|
| `_id` | `ObjectId` | Уникальный идентификатор группового чата |
| `name` | `string` | Название чата |
| `description` | `string` | Описание чата |
| `created_by` | `ObjectId` | Ссылка на пользователя-создателя |
| `members` | `array` | Встроенный список участников |
| `members.user_id` | `ObjectId` | Ссылка на пользователя |
| `members.role` | `string` | Роль пользователя в чате |
| `members.joined_at` | `date` | Дата вступления в чат |
| `created_at` | `date` | Дата создания чата |
| `updated_at` | `date` | Дата последнего изменения |

Состав участников хранится как embedded-массив внутри документа чата. Эта информация относится именно к чату и часто нужна вместе с ним: при проверке доступа, отображении состава, добавлении пользователя. При этом сам пользователь не встраивается полностью: в `members.user_id` хранится ссылка на документ из `users`.

Сообщения не встраиваются в `group_chats`, потому что история чата может быть большой. Если хранить сообщения массивом внутри чата, документ будет постоянно расти, а загрузка старых сообщений станет неудобной. Поэтому сообщения групповых чатов вынесены в `group_messages`.

## 5. Коллекция `group_messages`

Документ сообщения группового чата:

```json
{
  "_id": {
    "$oid": "665000000000000000000201"
  },
  "chat_id": {
    "$oid": "665000000000000000000101"
  },
  "sender_id": {
    "$oid": "665000000000000000000001"
  },
  "text": "Коллеги, завтра обсуждаем API.",
  "created_at": {
    "$date": "2026-05-25T10:20:00Z"
  },
  "edited_at": null
}
```

Назначение полей:

| Поле | Тип | Описание |
|---|---|---|
| `_id` | `ObjectId` | Уникальный идентификатор сообщения |
| `chat_id` | `ObjectId` | Ссылка на групповой чат |
| `sender_id` | `ObjectId` | Ссылка на отправителя |
| `text` | `string` | Текст сообщения |
| `created_at` | `date` | Дата отправки |
| `edited_at` | `date/null` | Дата редактирования, если сообщение изменяли |

Сообщение хранится отдельным документом и ссылается на групповой чат через `chat_id`. Это упрощает загрузку истории: можно выбирать сообщения конкретного чата с сортировкой по `created_at` и ограничением количества записей.

## 6. Коллекция `ptp_chats`

Документ PtP-чата:

```json
{
  "_id": {
    "$oid": "665000000000000000000301"
  },
  "participant_ids": [
    {
      "$oid": "665000000000000000000001"
    },
    {
      "$oid": "665000000000000000000002"
    }
  ],
  "participant_key": "665000000000000000000001:665000000000000000000002",
  "created_at": {
    "$date": "2026-05-25T10:30:00Z"
  },
  "updated_at": {
    "$date": "2026-05-25T10:35:00Z"
  }
}
```

Назначение полей:

| Поле | Тип | Описание |
|---|---|---|
| `_id` | `ObjectId` | Уникальный идентификатор PtP-чата |
| `participant_ids` | `array<ObjectId>` | Два пользователя, между которыми идет переписка |
| `participant_key` | `string` | Упорядоченный ключ пары участников |
| `created_at` | `date` | Дата создания чата |
| `updated_at` | `date` | Дата последнего сообщения или изменения |

PtP-чат хранится отдельно, потому что это самостоятельная сущность: у него есть два участника и история сообщений. Участники представлены ссылками на `users`, так как один пользователь может участвовать во множестве личных чатов.

Список участников можно хранить embedded-массивом, потому что в PtP-чате всегда два участника. Полные документы пользователей не встраиваются, чтобы данные профиля не дублировались.

Поле `participant_key` формируется из двух `ObjectId`, отсортированных в одном порядке. Оно нужно, чтобы не создавать два разных PtP-чата для одной пары пользователей.

## 7. Коллекция `ptp_messages`

Документ PtP-сообщения:

```json
{
  "_id": {
    "$oid": "665000000000000000000401"
  },
  "chat_id": {
    "$oid": "665000000000000000000301"
  },
  "sender_id": {
    "$oid": "665000000000000000000001"
  },
  "receiver_id": {
    "$oid": "665000000000000000000002"
  },
  "text": "Привет, посмотри, пожалуйста, макет API.",
  "created_at": {
    "$date": "2026-05-25T10:35:00Z"
  },
  "read_at": null
}
```

Назначение полей:

| Поле | Тип | Описание |
|---|---|---|
| `_id` | `ObjectId` | Уникальный идентификатор сообщения |
| `chat_id` | `ObjectId` | Ссылка на PtP-чат |
| `sender_id` | `ObjectId` | Ссылка на отправителя |
| `receiver_id` | `ObjectId` | Ссылка на получателя |
| `text` | `string` | Текст сообщения |
| `created_at` | `date` | Дата отправки |
| `read_at` | `date/null` | Дата прочтения |

PtP-сообщения вынесены в отдельную коллекцию по той же причине, что и сообщения групповых чатов: история переписки может быть большой. Для получения списка сообщений пользователя можно искать сообщения по `sender_id` или `receiver_id`, а для загрузки конкретного диалога - по `chat_id`.

## 8. Embedded documents и references

| Связь | Решение | Обоснование                                                                                               |
|---|---|-----------------------------------------------------------------------------------------------------------|
| `group_chats.created_by` - `users` | Reference | Создатель - отдельный пользователь, который может участвовать во многих чатах                             |
| `group_chats.members` - `users` | Embedded-массив со ссылками | Состав участников относится к чату и часто нужен вместе с ним, но профиль пользователя остается в `users` |
| `group_messages.chat_id` - `group_chats` | Reference | Сообщений может быть много, их нужно загружать постранично                                                |
| `group_messages.sender_id` - `users` | Reference | Отправитель является отдельной сущностью и может иметь много сообщений                                    |
| `ptp_chats.participant_ids` - `users` | Embedded-массив со ссылками | В PtP-чате всегда два участника, поэтому массив небольшой и стабилен                                      |
| `ptp_messages.chat_id` - `ptp_chats` | Reference | История личной переписки может расти без ограничений                                                      |
| `ptp_messages.sender_id` - `users` | Reference | Один пользователь может отправлять много сообщений                                                        |
| `ptp_messages.receiver_id` - `users` | Reference | Один пользователь может получать много сообщений                                                          |

## 9. Индексы

Для поддержки требуемого API нужны следующие индексы:

```javascript
db.users.createIndex({ login: 1 }, { unique: true })
db.users.createIndex({ first_name: 1, last_name: 1 })

db.group_chats.createIndex({ "members.user_id": 1 })

db.group_messages.createIndex({ chat_id: 1, created_at: -1 })
db.group_messages.createIndex({ sender_id: 1 })

db.ptp_chats.createIndex({ participant_ids: 1 })
db.ptp_chats.createIndex({ participant_key: 1 }, { unique: true })

db.ptp_messages.createIndex({ chat_id: 1, created_at: -1 })
db.ptp_messages.createIndex({ sender_id: 1, created_at: -1 })
db.ptp_messages.createIndex({ receiver_id: 1, created_at: -1 })
```

Индекс по `login` нужен для быстрого поиска пользователя и контроля уникальности логина. Индекс по `first_name` и `last_name` используется для поиска по маске имени и фамилии. Индексы по сообщениям нужны для загрузки истории чатов и списка PtP-сообщений пользователя.

## 10. Соответствие API

| Требование API | Коллекции |
|---|---|
| Создание нового пользователя | `users` |
| Поиск пользователя по логину | `users` |
| Поиск пользователя по маске имени и фамилии | `users` |
| Создание группового чата | `group_chats` |
| Добавление пользователя в чат | `group_chats.members` |
| Добавление сообщения в групповой чат | `group_messages` |
| Загрузка сообщений группового чата | `group_messages` |
| Отправка PtP-сообщения пользователю | `ptp_chats`, `ptp_messages` |
| Получение PtP-списка сообщений для пользователя | `ptp_messages` |
