# Домашнее задание 01: Система управления проектами

## Описание задания

**Вариант** - Управление проектами (https://www.atlassian.com/ru/software/jira)

### Данные системы

Приложение должно содержать следующие данные:
- проект;
- задача;
- исполнитель.

### API требования

Система должна реализовывать следующие API:
- создание нового пользователя;
- поиск пользователя по логину;
- поиск пользователя по маске имя и фамилии;
- создание проекта;
- поиск проекта по имени;
- поиск всех проектов;
- создание задачи в проекте;
- получение всех задач в проекте;
- получение задачи по коду.

## Архитектурное решение

### Роли пользователей

1. **Участник проекта** - работает с проектами и задачами, просматривает задачи проекта, открывает задачу по коду, ищет коллег по логину, имени или фамилии.

2. **Руководитель проекта** - создает проекты и задачи, назначает исполнителей, контролирует состав задач внутри проекта.

3. **Администратор системы** - создает пользователей, проверяет пользовательские данные и управляет базовыми настройками доступа.

### Внешние системы

1. **Сервис корпоративной аутентификации** - проверяет учетные данные пользователей и токены доступа.

2. **Email-сервис** - отправляет уведомления о создании учетной записи, создании задачи и назначении исполнителя.

3. **Корпоративный мессенджер** - отправляет уведомления в командные каналы и личные сообщения.

4. **Система контроля версий** - хранит ветки, коммиты и pull request, связанные с задачами.

### Контейнеры системы

1. **Web Application** (React, TypeScript) - веб-интерфейс для работы с пользователями, проектами и задачами.

2. **API Gateway** (Kong, Nginx, REST API) - единая точка входа для запросов клиентского приложения.

3. **User Service** (Python, FastAPI, REST API) - создание пользователя, поиск по логину, поиск по имени и фамилии.

4. **Project Service** (Python, FastAPI, REST API) - создание проекта, поиск проекта по имени, получение списка всех проектов.

5. **Task Service** (Python, FastAPI, REST API) - создание задачи в проекте, получение задач проекта, получение задачи по коду.

6. **Notification Service** (Python, FastAPI, AMQP Consumer) - обработка событий и отправка уведомлений.

7. **User Database** (PostgreSQL) - хранение данных пользователей.

8. **Project Database** (PostgreSQL) - хранение данных проектов.

9. **Task Database** (PostgreSQL) - хранение данных задач.

10. **Cache** (Redis) - кэширование пользователей по логину, проектов по имени и списка проектов.

11. **Message Queue** (RabbitMQ) - передача доменных событий между сервисами.

### Основные сценарии взаимодействия

#### Создание пользователя

Администратор создает пользователя через Web Application. Запрос проходит через API Gateway в User Service. User Service сохраняет пользователя в User Database, обновляет Cache и публикует событие `UserCreated`. Notification Service получает событие и отправляет email-уведомление.

#### Поиск пользователя

Пользователь выполняет поиск по логину или по маске имени и фамилии. API Gateway передает запрос в User Service. Поиск по логину использует Cache, поиск по имени и фамилии выполняется в User Database.

#### Создание проекта

Руководитель проекта создает проект через Web Application. Project Service проверяет уникальность имени и кода проекта, сохраняет проект в Project Database, обновляет Cache и публикует событие `ProjectCreated`.

#### Поиск и получение проектов

Пользователь ищет проект по имени или запрашивает список всех проектов. Project Service использует Cache для часто запрашиваемых данных и Project Database как основной источник данных.

#### Создание задачи в проекте

Руководитель проекта создает задачу в выбранном проекте. Task Service проверяет проект через Project Service, проверяет исполнителя через User Service, сохраняет задачу в Task Database и публикует события `TaskCreated` и `TaskAssigned`. Notification Service отправляет уведомления исполнителю и команде.

#### Получение задач проекта

Пользователь открывает список задач проекта. Task Service проверяет проект через Project Service, читает задачи из Task Database и дополняет ответ данными исполнителей из User Service.

#### Получение задачи по коду

Пользователь открывает задачу по уникальному коду. Task Service читает задачу из Task Database, получает данные проекта и исполнителя, а также запрашивает связанные изменения в системе контроля версий.

### Технологии и протоколы

**Frontend:**
- React;
- TypeScript;
- HTTPS/REST.

**Backend:**
- Python;
- FastAPI;
- Kong или Nginx;
- REST API.

**Data Layer:**
- PostgreSQL;
- Redis;
- RabbitMQ.

**Protocols:**
- HTTPS - доступ пользователей к Web Application;
- HTTPS/REST - взаимодействие Web Application, API Gateway и внутренних сервисов;
- OAuth2/OIDC - проверка токенов доступа;
- JDBC/SQL - работа сервисов с PostgreSQL;
- Redis Protocol - работа с кэшем;
- AMQP - обмен событиями через Message Queue;
- SMTP - отправка email.

## Диаграммы

### System Context (C1)

Показывает систему управления проектами в контексте пользователей и внешних систем.

### Container (C2)

Показывает внутренние контейнеры системы и связи между ними.

### Dynamic - CreateTask

Показывает последовательность создания задачи в проекте: проверку проекта, проверку исполнителя, сохранение задачи и отправку уведомлений.
